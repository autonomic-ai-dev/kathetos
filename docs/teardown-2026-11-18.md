# Teardown · 50 real commits, one afternoon

Two of my own repos, both histories, no synthetic data except the four hard-rule
proofs at the end.

| Repo | Language | Commits | `Cargo.lock` |
|---|---|---|---|
| `tekmor` | Rust | 346 | 571 packages |
| `agentrun` | Go | 77 | n/a |

**Method.** `kathetos check --diff <rev>^...<rev>`, warm page cache, macOS,
day-old binary. Every number below comes from the tool, not from a shell one-liner.

**Headline.** Across 50 commits: **0 hard violations, 3 advisory findings, median
39ms, p95 77ms, max 88ms.** Draft 1 of the rules produced 14 findings on the same
corpus, 11 of them wrong. The rest of this document is about that gap.

## 1. `tekmor 05b3c69` — 7 dependencies for one feature

`v0.7.0 encrypted cloud sync and secret refs`, 15 files.

```
kathetos · rust · 15 files · 48ms · deps +7 -> +75 pkg (220 in tree) · tests 0
forks: 3
1. agent-brain/Cargo.toml:17  7 direct deps for one change
   native: ship the part of the feature that needs none of them
   6mo:    +75 packages, 220 already in the tree
   ask:    which of these does the diff call directly?
2. agent-brain/Cargo.toml:17  age added (12 refs)
   native: the age binary as a subprocess, or ssh-key encryption
   6mo:    +51 packages
   ask:    is the key material ever handled in-process?
3. agent-brain/Cargo.toml:23  keyring added (1 ref)
   native: OS keychain CLI: security find-generic-password / secret-tool
   6mo:    +1 package
   ask:    does this need to work on more than one OS in v1?
```

The seven: `age`, `keyring`, `opendal`, `secrecy`, `tar`, `zstd`, `tempfile`.
Cargo.lock grew by **79 packages**, 75 of them reachable from those seven.

What arrived, measured from the lockfile diff:

- `quinn`, `quinn-proto`, `quinn-udp` — an entire QUIC implementation.
- `fluent`, `fluent-bundle`, `fluent-syntax`, `i18n-embed`, `intl_pluralrules` —
  an internationalisation framework.
- `qoi` — an image codec.
- `reqsign`, `opendal`, `zstd-sys`, `chacha20poly1305`, `curve25519-dalek` …

The receipt's job is not to say "bad". Three of those seven are called directly in
the diff (`age` 12 times, `tar`, `zstd`), so the fork is not "remove it" — it is
*"this feature was scoped as seven crates, and four of them are subsystems the
feature does not mention."* The number that makes the argument is `+75`, and it
took a lockfile graph to get it: `+1 direct` alone is a rounding error.

Note the `220 already in the tree`. Without the old lockfile, a tool would report
`+295` and be wrong by a factor of four in the other direction. Measuring beats
asserting in both directions.

## 2. `tekmor 1d462a3` — rayon, and the cost was zero

The anti-demo. `fix: resolve index timeout by parallelizing file discovery`, 4 files.

```
kathetos · rust · 4 files · 50ms · deps +1 -> +0 pkg (5 in tree) · tests 0
forks: 1
1. agent-brain/Cargo.toml:54  rayon added (2 refs)
   native: std::thread::scope over chunks
   6mo:    +0 packages: already in the tree
   ask:    is the work CPU-bound or IO-bound?
```

The naive version of this tool says "rayon: +5 transitive crates". The measured
version says **+0 new packages, 5 already present**. The fork survives, but its
question changes completely: not *"is 5 crates worth it"* (it was free) but
*"should this binary own a second thread pool"*.

A receipt that cannot say "free" is a receipt nobody believes.

## 3. `agentrun` — the commits that broke my rules

### `fbea8a7` — four skips, all honest

```
kathetos · go · 91 files · 77ms · tests 0
forks: 1
1. internal/projectx/runner_test.go:32  test skipped (reason given) (x4)
```

Draft 1 blocked this commit with four `t.Skip added` violations. All four read:

```go
t.Skip("project-x binary not found; set PROJECT_X_HOME to a project-x checkout to run this test")
```

That is not cheating. It is a test that cannot run without a checkout on disk, and
it says so. A skip with a stated reason is a decision someone can review; a bare
`t.Skip()` is not. The rule now blocks only the bare form.

### `ff6d513` — two tests deleted, and they were live tests

Draft 1 blocked: `test removed with no replacement`. The two deleted functions
were `TestLivePromptAgyThroughEgressProxy` and
`TestLivePromptCursorThroughEgressProxy` — tests that require a real agent binary
and a real network. Deleting those is maintenance, not coverage loss.

The rule now reads the deleted function's body from the *old* blob and checks for
`os.Getenv`, `exec.Command`, `http.`, `net.Dial`, or a name containing
`Live`/`Integration`. External → fork. Hermetic → block.

### The eleven findings that were wrong

| Draft-1 rule | Fired | Correct | Precision |
|---|---|---|---|
| `t.Skip(...)` of any kind | 4 | 0 | 0% |
| `#[test]`/`func Test` deleted | 2 | 0 | 0% |
| `.unwrap()` outside `main.rs` | 6 | 0 | 0% |
| `_ =` not `fmt.Fprint`/`Close` | 5 | 0 | 0% |
| assertion count dropped | 1 | 1 | 100% |
| dependency delta | 8 | 8 | 100% |

The `.unwrap()` hits were all inside `#[cfg(test)]` modules or `tests/`. The
`_ =` hits were `syscall.Flock`, `f.Close()`, a `DeleteNetwork` on an error path
that already returns the primary error, and a best-effort `exec.Command` stop.

That is 0/11. Not "noisy" — wrong. Every one of those rules asks a question that
the text of a diff cannot answer:

> Is this ignored error actionable?

You cannot answer that from the spelling of the line. You need to know what the
callee does, who calls this, and what the caller already validated. That is a
judgement, and a deterministic binary does not get to have one.

Meanwhile the two rules with an actual data structure behind them — an assertion
count and a lockfile graph — were right every time.

## What changed

1. **Cut `.unwrap()` and `_ =` from the checker.** They remain skill cards, where
   a human is in the loop. The check keeps only `http.Client{}` without a
   `Timeout`, which is unambiguous (no timeout in the same file is not a style
   opinion).
2. **A skip blocks only when it has no reason.** A reason is a reviewable
   decision; silence is not.
3. **A deleted test blocks only if it was hermetic.** Otherwise it is a fork.
4. **Repeat findings collapse.** Four identical skips are one finding `(x4)`, not
   four lines.

After those four edits, on the same 50 commits: **0 hard violations, 3 forks**
(one reasoned skip, one live-test removal, one assertion drop), each of which is
something I would actually want to see.

## What this does not prove

50 commits, two repos, one author. The four hard rules are validated on synthetic
diffs plus two real live-test deletions; that is enough to know they do not fire
on honest work, not enough to claim a false-negative rate. Go dependency
attribution is not implemented — `go.sum` has no edges, and the tool says so
rather than guessing. `http.Client` has zero hits on this corpus, so its precision
is unmeasured.

The honest summary: **the dependency delta and the assertion counter are real
checks. The rest of v0.1 is a receipt, and a receipt is allowed to say "I don't
know."**
